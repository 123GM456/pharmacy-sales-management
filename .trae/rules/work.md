请严格遵循以下代码风格和注释规范。

# 一、代码风格

1. 使用标准 Java 命名规范：
   - 类名：PascalCase
   - 方法名、变量名：camelCase
   - 常量：UPPER_CASE

2. 保持代码结构清晰、职责明确，避免过长或过于复杂的单行代码。

3. 只编写实际需要的代码，不为了增加代码量而重复或堆砌代码。

4. 保持代码简洁、规范、易读。

5. 除非我明确要求，否则不要擅自修改或删除已有代码。

# 二、注释规范

1. 每个 Java 类都要在类声明前添加简洁的功能简介，说明类是什么、主要负责什么以及在项目中的作用。

2. 如果注释只有一句话，必须使用 `//` 单行注释。

3. 如果使用多行注释，每一行应表达独立的信息点，不要把同一句话机械拆成多行，也不要重复表达相同含义。

4. 每个 `import` 上方都要使用一行 `//` 注释，简要说明为什么需要导入该类或包。
参考// 导入 LocalDateTime：表示年月日时分秒，对应数据库的 DATETIME 类型

5. 重要方法使用 JavaDoc，必要时说明方法功能、参数、返回值和异常。

6. 对复杂逻辑添加必要的行级或代码块注释，重点解释“做什么”和“为什么这样做”。

7. 以下内容应重点添加注释：
   - 复杂业务逻辑
   - SQL/JDBC 操作
   - 异常处理
   - 事务
   - 多线程
   - 不容易理解的代码

8. 简单直观的代码，如 getter/setter、简单赋值、简单判断等，不添加冗余注释。

9. 注释必须准确反映实际代码功能，不得出现注释与代码不一致的情况。

10. 注释使用中文，代码标识符使用规范的英文命名。

总体原则：

“类有简介，import 有用途说明，重要方法有说明，复杂逻辑有解释，简单代码不注释，不为了凑代码量堆砌代码或注释。”
